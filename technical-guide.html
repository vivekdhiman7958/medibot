01 · Scope and status

What this document describes

This guide describes the code currently in the MediBot project—not a production deployment and not every feature proposed in the original architecture PDF.

Implemented
  • Bun HTTP server and static browser UI
  • TypeScript tool-calling agent using Groq
  • SQLite catalogue and safety-term tables
  • CSV importer for the downloaded 1mg Kaggle file
  • Optional Tavily web search for selected medical-reference domains
  • Input, tool, and generated-answer checks
  • Disclaimer acknowledgement and in-memory chat context
Not yet implemented / not verified
  • Complete official restricted-drug data
  • MID workbook ingestion or composition normalization
  • Live pharmacy APIs, permitted scraping, or real-time stock
  • Nearby places or location-based search
  • Production authentication, deployment, monitoring, or audit trail
  • Clinical-grade accuracy validation
Intended use: prototype and educational demonstration only. It is not a medical device, pharmacist, or substitute for professional advice. Do not use it to make medication decisions.

The initial project architecture PDF defines the desired problem and guard flow. This guide records implementation status as of October 2026; scope gaps are called out instead of presented as completed features.

Why the stack fits a prototype

Bun provides a compact TypeScript runtime with a built-in SQLite API, avoiding a separate database server for a local demo. Plain browser assets keep the interface dependency-light. External models and search are called server-side so provider keys do not go to the browser.

Configuration: local secrets belong in the ignored .env file. The checked-in .env.example documents names only. Never commit API keys or include them in screenshots/PDFs.

04 · Request lifecycle

Chat request, guard by guard

  1. Session: browser sends POST /api/session after the user acknowledges the disclaimer. Server inserts an acknowledgement timestamp and generates a random session ID.
  2. Validate: POST /api/chat checks that the session exists and the message contains 1–2,000 characters.
  3. Guard 1: the server checks restricted-term fuzzy matching and a limited indirect-phrase rule on every message. On a match, it returns the required hardcoded line before calling Groq.
  4. Context: last messages are kept in server memory (bounded to six user/assistant turns). This map resets when the server process restarts.
  5. Agent: Groq receives the system instructions and local tools. If Tavily is configured, the medical-search tool is also available.
  6. Tool guards: each catalogue tool checks its medicine input before querying data. Web-search queries are checked before the Tavily request.
  7. Guard 2: generated response text is checked for known restricted names and a small set of diagnosis phrases; the agent may request up to two rewrites.
  8. Render: response text, source list, and internet-information notice are returned to the browser; citation links are shown separately.
Important boundary: these checks cannot guarantee detection of every restricted product, brand, misspelling, or diagnosis phrase. The bundled restricted list is incomplete demo data, and the output-language matcher is not a clinical classifier.

05 · SQLite model

Database tables and relationships

medicines 1 ─── * prices medicines 1 ─── 0..1 health_info restricted_terms (independent safety vocabulary) sessions (disclaimer acknowledgement metadata)
TableMain fieldsMeaning / limitation
medicinesid, brand, manufacturer, composition, normalized_composition, mrp, restricted, pack_size, rating, data_source, source_price, source_mrpProduct row. Imported CSV lacks ingredient/manufacturer; these fields are marked unprovided, not inferred.
pricesmedicine_id, pharmacy, price, eta_days, in_stock, source_typeSource price snapshot or earlier simulated demo values. Imported rows have unknown stock and ETA.
health_infomedicine_id, side_effects, interactionsOnly old demo seed records; these are cleared when the importer replaces the catalogue.
restricted_termsterm, ingredientCurrently eight demonstration aliases/ingredient terms, not an official list.
sessionsid, disclaimer_acknowledged_at, created_atPersists session acknowledgement metadata. Conversation text is not stored here.

Foreign keys are enabled. Deleting medicines cascades to dependent prices and health-info rows. The 1mg importer uses a transaction when replacing medicine rows, preserving the independent sessions and restricted-term table.

Privacy note: chats are stored only in process memory; however session IDs and acknowledgement timestamps persist in SQLite. There is no production account system, deletion workflow, or multi-process session store.

07 · Agent tools

What the model can call

ToolData boundaryImportant behavior
get_compositionSQLite medicine recordImported 1mg rows report composition unavailable; model must not fill it from memory.
find_alternativesExact normalized composition and strengthReturns no suggestions for entries marked unverified. Kaggle file has no composition field.
compare_pricesSQLite price recordsDistinguishes Kaggle snapshots from simulated demo values; no live pharmacy feed exists.
get_drug_infoSQLite health_infoKaggle data does not provide this information; old demo health rows are removed by catalogue import.
search_medical_web (optional)Tavily excerpts from allow-listed domainsOne search per agent call; produces HTTPS citations. Not used to decide restriction status or prescribe.

Web source policy implemented

Search requests use Tavily with domains including MedlinePlus, NHS, DailyMed, FDA, CDSCO, WHO, and NCCIH. Results require HTTPS, duplicate links are skipped, and excerpts containing a known restricted term are discarded. The agent prompt labels excerpts untrusted and tells the model not to follow instructions in them.

Privacy: the generated general search query is sent to Tavily. A small pattern blocks some personal-looking queries, but this is not a complete privacy detector. Users are told not to include personal identifiers or private health details.

Citations: source title and URL are sent separately to the browser; the UI validates HTTPS before making external links and opens them with noopener noreferrer. If no excerpts are returned, the agent is instructed not to answer from memory.

08 · Safety, trust & security

Safety is layered—and still incomplete

LayerCurrent mechanismResidual risk
InputKnown terms, simple edit-distance typo matching, selected indirect-reference patternsSmall demo vocabulary; unseen brand names, languages, phrasing, ingredient aliases, or misspellings may pass.
Tool inputCatalogue tools re-run restricted-term checksSame incomplete list; only protects paths that match the current checks.
OutputRestricted-name scan and regex for some diagnosis phrases; up to two rewritesLanguage rules do not understand all clinical claims or context and cannot guarantee zero unsafe outputs.
AlternativesDatabase query requires identical normalized composition/strengthImported Kaggle rows have no composition and therefore cannot be compared.
SourcesTrusted-domain search and visible citationsDomain allow-list does not mean every page is accurate or relevant; users should verify source and date.

Credential and data-handling points

  • Groq and Tavily keys are server-side environment variables and should remain only in local .env, which is gitignored.
  • Search queries are sent to an external provider; avoid submitting personal or sensitive information.
  • There is no user login, rate limit, CSRF defense, production TLS configuration, or deployment hardening in this local prototype.
  • Do not expose the dev server to the public internet or treat it as a clinical service.
Before real use: replace the small seed vocabulary with an authoritative and reviewed restricted list, develop a representative safety test set, measure false blocks and misses, and obtain qualified compliance/clinical review.

09 · Local setup and operations

Run, configure, import, verify

  1. 1Install Bun, open the project folder, and run bun install.
  2. 2Copy .env.example to .env; set GROQ_API_KEY. Default model: openai/gpt-oss-120b.
  3. 3Optionally set TAVILY_API_KEY for cited web fallback.
  4. 4Start with bun run dev; open http://localhost:3000. If port 3000 is occupied, stop the existing server before starting another.
  5. 5Check GET /api/health for groqConfigured and webSearchConfigured. These are booleans; API keys are not returned.
  6. 6Run bun run import:1mg:check to preview the CSV, then bun run import:1mg to replace catalogue products.
  7. 7Verify with bun run typecheck and bun test.
Importer effect: importing replaces medicine rows and cascades deletion of dependent prices and health-info rows. It retains sessions and restricted terms. Back up data/medibot.sqlite before future reimports if its records matter.

10 · Roadmap

Recommended path forward

Data quality

Establish provenance

Record dataset owner/source URL, version or capture date, license, attribution, and transformation rules. Resolve the source price/MRP anomaly before savings calculations.

Safety

Authoritative restrictions

Obtain official current restricted-drug sources; normalize ingredient and brand aliases; get qualified review; expand regression and typo tests.

Composition

Validated matching

Inspect MID workbook schema and license. Normalize ingredients, strengths, salts, dosage form, and pack size. Keep confidence/provenance per match.

Pricing

Approved current feed

Use a partner API or explicitly permitted source. Store timestamp, product identifier, pack, availability, and provenance for every quote.

Operations

Harden deployment

Add authentication if needed, rate limits, request timeouts, secure hosting/TLS, secret management, monitoring, and privacy/deletion policies.

Evaluation

Measure before claims

Evaluate catalogue matching, citation quality, restriction recall/false blocks, diagnosis-language escapes, latency, and user feedback.

Scope reminder: the current application uses web search for general reference fallback, not pharmacy scraping. Add no scraper until the target source's terms and permission explicitly allow it.
