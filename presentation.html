MEDIBOT · PROTOTYPE01

01 · THE IDEA

Useful information, with clear boundaries

People often need to find a product in a large catalogue, understand what data is actually available, and know where an answer came from. MediBot brings those steps into a conversational interface.

Find

Catalogue lookup

Search imported product names and pack sizes from a local SQLite catalogue.

Compare

Price snapshots

Show source-provided values and label their origin—not as a live pharmacy offer.

Explain

Sourced answers

Optional medical-reference web search returns clickable source links.

Product principle: an empty or incomplete dataset is not a reason to invent facts. Say what is missing, preserve provenance, and keep medical decisions with qualified professionals.

02 · REQUEST JOURNEY

From a question to a bounded answer

1 · AskUser acknowledges the medical disclaimer and sends a question.
›
2 · GuardServer checks known restricted terms and high-signal indirect phrasing.
›
3 · RetrieveGroq can call guarded SQLite tools; Tavily is optional for general references.
›
4 · CheckGenerated text is checked for restricted names and diagnosis language.
›
5 · CiteWeb-based answers display HTTPS source links and a general-info notice.
Local first

Medicine records and price snapshots are read from SQLite. Prices are never sourced from model memory.

Web as fallback

When enabled, general reference search is domain-limited. It is not a pharmacy scraper or a source of live prices.

03 · BUILD

A small, understandable stack

Runtime & language

Bun + TypeScript

Runs the HTTP server, installs project tooling, and executes the TypeScript application.

Persistence

SQLite

Stores medicine records, snapshot prices, restriction terms, health info, and disclaimer acknowledgement timestamps.

Language model

Groq · gpt-oss-120b

Interprets questions and formats tool results. Code and database—not the model—own guard decisions.

Reference search

Tavily (optional)

Finds general medical-reference excerpts and returns the source links shown to the user.

04 · DATA REALITY

What the current dataset can—and can’t—say

15,948

Imported products

Distinct product rows loaded from the 1mg Kaggle CSV snapshot.

11,648

Price entries

Rows with a parseable source price. They are historical snapshot values, not live offers.

0

Verified compositions

The CSV has no ingredient field, so exact-composition alternatives are unavailable.

Available in the CSV

Product name, pack size, rating count, rating, price, and MRP.

Not supplied by this CSV

Verified ingredients, manufacturer, stock, delivery ETA, or capture date.

The source price exceeds the source MRP in many imported records. Both original columns are preserved without guessing what the labels mean.

05 · SAFETY BY DESIGN

Guardrails are code paths—not model promises

Input guard

Before the LLM

Known restricted terms and selected indirect phrases can return the mandated block response before any model call.

Tool guards

Before retrieval

Catalogue lookups re-check medicine terms. Search uses a limited domain allow-list and only one call per answer.

Output guard

After generation

Generated answers are checked for known restricted names and common diagnosis phrasing, with limited rewrites.

User notice

Source & role

Web answers show links and say the information is general—not diagnosis or treatment advice.

Prototype limitation: the restricted-term list currently contains only a small demonstration sample. It is not a complete, official Schedule H list; do not rely on this app for medication decisions.
